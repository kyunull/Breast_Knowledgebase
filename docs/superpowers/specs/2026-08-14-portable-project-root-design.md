# 可移动项目根目录设计

日期：2026-08-14

## 目标

知识库可以克隆或移动到任意本地绝对路径，包括 C、D、E 等磁盘，而不需要修改应用代码、数据库记录或运维脚本。程序产生的数据库、索引、模型、报告和临时缓存仍必须位于当前项目目录内。

## 用户体验

- 用户可把仓库放在任意目录，例如 `C:\Projects\knowledgebase` 或 `E:\team\knowledgebase`。
- Python 服务、导入命令和快照验证命令从代码文件位置自动发现项目根目录，不依赖 PowerShell 当前工作目录。
- PowerShell 初始化脚本从脚本自身位置发现项目根目录，不再要求固定的 D 盘路径。
- PDF、HTML 和 JSONL 是只读输入，可位于任意磁盘，但必须使用存在的绝对文件路径。
- 所有可写目录继续位于 `<项目根目录>\data`，环境变量不得将可写路径指向项目外。
- 项目移动后，已有 SQLite、托管资料和 LlamaIndex 快照可以继续使用。

## 根目录发现

新增一个单一的项目路径模块，负责从已安装的 `app` 包位置计算仓库根目录。应用入口、`GuidelineService`、导入脚本、快照验证脚本和源契约功能都使用该模块，不再分别声明固定的 `PROJECT_ROOT`。

`Settings.from_env` 保留显式传入 `project_root` 的能力，供测试和嵌入式调用使用；未传入时采用自动发现结果。显式根目录只要求是绝对、已解析的目录，不限制盘符。

`bootstrap_runtime.ps1` 默认使用 `$PSScriptRoot` 的父目录。若调用者显式传入 `-ProjectRoot`，该路径必须与脚本所属仓库相同，防止一个仓库的脚本向另一个目录写入运行数据。

## 写入边界

以下路径仍由 `Settings` 统一创建和校验：

- `data`
- SQLite 注册表
- 托管源文件目录
- LlamaIndex 快照目录
- BGE-M3 模型缓存
- pip、Hugging Face、Transformers、PyTorch 和临时缓存

每个路径解析后都必须是当前项目根目录的子路径。项目可以位于 C 盘，但程序不能把其中某一类运行数据单独写到项目外。

源文件不属于可写运行数据。导入和源契约校验删除 D 盘限制，只保留“绝对路径、文件存在、只读使用”的要求。

## 持久化路径

新导入版本在 SQLite 中保存项目相对路径：

- `document_version.snapshot_path` 保存相对于项目根目录的快照路径。
- `source_file.managed_path` 保存相对于项目根目录的托管副本路径。
- `source_file.original_path` 继续保存提交导入时的外部绝对路径，用于来源审计，不要求目标设备仍能访问。

服务使用持久化路径前，统一将相对路径解析到当前项目根目录，并再次执行项目内路径校验。快照仍按指南 ID、版本 ID、manifest 和组件哈希验证，不能仅凭路径存在就加载。

## 旧数据迁移

现有数据库保存了 `D:\coding\knowledgebase\data\...` 绝对路径。服务首次使用旧数据库时执行一次事务化迁移：

1. 根据指南版本和现有文件名计算当前项目下的规范快照及托管文件位置。
2. 验证所有目标路径位于当前项目内且对应文件真实存在。
3. 全部验证通过后，在同一 SQLite 事务中把运行路径改成项目相对路径。
4. 写入一条 `project_paths_rebased` 追加式审计事件，记录迁移数量，不记录外部凭据或文件内容。
5. 后续启动检测到路径已经相对化时不再修改数据库，也不重复写审计。

如果任何目标文件缺失、路径逃逸项目目录或出现冲突，迁移整体回滚并列出错误对象。程序不读取旧设备上的绝对路径，也不静默创建空索引。

迁移不修改版本状态、审批时间、源文件哈希、快照 manifest 或版本差异。CACA active、r2 draft 和 r3 draft 的生命周期保持不变。

## 接口调整

- `GuidelineService` 只验证所有可写设置属于 `settings.project_root`，不再与一个模块级固定常量比较。
- `GuidelineLifecycle` 不再限制项目盘符，仍验证托管目录和索引目录属于项目根目录。
- `build_source_contract_report` 接收或发现当前项目根目录，用它限制报告输出路径；输入源只要求是存在的绝对文件。
- `load_ingest_config` 默认使用自动发现根目录限制配置文件位置，同时允许测试显式提供其他根目录。
- FastAPI 的公开请求和响应结构不变。

## 错误处理

- 相对源文件路径：拒绝并提示必须提供绝对路径。
- 不存在的源文件：拒绝并返回具体文件路径。
- 可写路径位于项目外：启动前拒绝，不创建目录。
- 旧数据库迁移目标缺失：整体回滚并说明缺失的版本或文件。
- 快照身份或哈希不一致：继续按现有完整性错误拒绝加载。

## 测试

实施采用测试先行，覆盖以下行为：

- 自动发现根目录不受当前工作目录影响。
- 项目根目录可以位于任意盘符或临时目录。
- 所有默认运行目录仍位于项目根目录内。
- 项目外的数据库、索引、模型或缓存路径仍被拒绝。
- 任意磁盘的绝对源路径可以导入，源路径为相对路径时仍被拒绝。
- 新版本把快照和托管文件路径保存为项目相对路径。
- 旧绝对路径数据库能迁移并加载现有快照。
- 缺失文件时迁移整体回滚，审计和版本状态不发生部分更新。
- PowerShell 初始化脚本可从任意仓库路径运行。
- 原有单元测试、CACA r3 单源契约、快照验证、编译和依赖检查继续通过。

## 文档与交付

README 和本地运行手册改用当前位置变量，不再要求 `D:\coding\knowledgebase`。数据包仍以 `data/` 为顶层目录，解压到任意项目根目录即可。历史设计文档保留原始决策记录，但当前 README 和运维文档以本设计为准。
